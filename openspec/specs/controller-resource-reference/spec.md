# controller-resource-reference Specification

## Purpose
The controller resource reference section at `/docs/reference/controller/` ("Controller Reference", one page per kind): generated into the docs bundle by docs-kit from the CRDs and samples, its index completed by the committed intro, the test that keeps each entry's reconciler name true, and the check that every sample is admitted by the CRDs.

## Requirements

### Requirement: The resource reference is generated into the docs bundle

The controller resource reference SHALL be generated by docs-kit's `crd` extractor from `config/crd/bases` and `config/samples` when the controller's docs bundle is built, as the section `reference/controller/` (`/docs/reference/controller/`, titled "Controller Reference"): an index `reference/controller/_index.md` whose `## Kinds` table lists the kinds in the order ModuleInstance, ModulePackage, Platform, TransformerRegistration, and one page per kind at `reference/controller/<kind lower-cased>.md`. The committed `docs/site/reference/controller/_index.md` SHALL hold only authored front matter (no `type`) and intro, with no marker lines and no `## Kinds` heading, and the bundle SHALL show that intro first and the generated table after it.

#### Scenario: The authored intro completes the page

- **WHEN** the bundle is built
- **THEN** `reference/controller/_index.md` starts with the committed front matter (title "Controller Reference", `weight: 7`) and intro, followed by the `## Kinds` table

#### Scenario: A generated heading in the authored page is refused

- **WHEN** a contributor adds `## Kinds` to the committed index
- **THEN** `task docs:bundle:check` fails, naming the page and the heading

#### Scenario: Each kind has its own page

- **WHEN** the bundle is built
- **THEN** `reference/controller/` holds `moduleinstance.md`, `modulepackage.md`, `platform.md` and `transformerregistration.md`, each titled with its kind and with `## At a glance` as its first heading

### Requirement: The reconciler each entry names is the one that reconciles the kind

`docs-kit.cue`'s `reconciledBy` SHALL map each of the four kinds to the `Named(...)` value of the reconciler whose builder in `internal/controller` calls `For(&v1alpha1.<Kind>{})`. A test run by `task dev:test` SHALL fail, naming the kind, when the two differ.

#### Scenario: A renamed reconciler fails the test

- **WHEN** a contributor changes `Named("platform")` to `Named("platform-reconciler")` and leaves `docs-kit.cue` as it was
- **THEN** the test fails, naming Platform and both names

#### Scenario: Agreeing names pass

- **WHEN** `docs-kit.cue` and the reconcilers agree
- **THEN** the test passes

### Requirement: Every sample is admitted by the CRDs

The `crdvalidation` integration tier SHALL dry-run create every `opmodel.dev` object in every `config/samples` file against the committed CRDs with strict field validation and fail on any rejection, so an example the reference shows is one the API server admits.

#### Scenario: Sample carries a field the schema does not have

- **WHEN** a sample in `config/samples` holds a field its CRD does not define
- **THEN** `TestSamplesAdmittedByTheCRDs` fails with the API server's unknown-field error for that sample
